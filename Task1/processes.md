### Как читать матрицу

- **Столбцы** — 8 процессов компании (те же, что в DFD-1…DFD-8).
- **Строки** — требования и архитектурные практики безопасности конфиденциальных данных.
- **Ячейки** — статус + ссылка на проблемную зону.
- **Вывод:** ни одна практика не реализована полностью ни в одном процессе; максимум — ⚠️ частично. Самые «дырявые» строки: классификация/теги, Data Lineage, аудит, MFA/PAM, API-контракты, изоляция пациентов.

## 1.2. Соответствие требованиям 152-ФЗ

| Статья 152-ФЗ | Требование | Затронутые процессы | Статус | Проблемная зона |
|---|---|---|---|---|
| **ст. 5** | Цели обработки, соответствие целям | Все процессы | ⚠️ | Цели не задокументированы, сбор избыточных данных (адрес, место работы) — ПЗ-5 |
| **ст. 6** | Правовые основания, согласие | Запись, медкарта, анализы | ❌ | Нет механизма сбора/отзыва согласия — ПЗ-5 |
| **ст. 9** | Согласие субъекта на обработку | Запись, медкарта, анализы | ❌ | Нет согласия на спецкатегории — ПЗ-5 |
| **ст. 10** | Спецкатегории (здоровье) | Медкарта, анализы, заключения | ❌ | Нет шифрования, нет спецрежима — ПЗ-4 |
| **ст. 18.1** | Меры по обеспечению безопасности | Все процессы | ⚠️ | Только доменная аутентификация — ПЗ-2 |
| **ст. 19** | Организационные и технические меры | Все процессы | ⚠️ | Нет RBAC/ABAC, аудита, DLP, SIEM — ПЗ-2/ПЗ-3/ПЗ-4/ПЗ-9 |
| **ст. 21** | Удаление по запросу субъекта | Все процессы | ❌ | Нет механизма удаления/прекращения обработки — ПЗ-5 |
| **ст. 22** | Уведомление РКН | — | ⚠️ | Не подтверждено в материалах |
| **Локализация (ст. 18 ч.5)** | Хранение ПДн на территории РФ | Все процессы | ⚠️ | Сервер в здании компании — ок, но нет резервирования |
| **Трансграничная передача (гл. 12)** | Уведомление/согласие | Интеграции с лабораторией | ⚠️ | Нет оценки будущих интеграций |

**Вывод:** по 152-ФЗ ключевые разрывы — ст. 10 (спецкатегории без шифрования), ст. 19 (нет технических мер), ст. 21 (нет удаления), ст. 6/9 (нет согласия). Это создаёт репутационные и финансовые риски, о которых говорит технический директор.

## 1.3. Целевая архитектура (To-Be) по практикам

| Практика / требование | Инструмент / механизм | Где внедряется |
|---|---|---|
| Privacy By Design | Политики в CI, шаблоны проектирования, threat modeling | Все новые сервисы (портал, CRM, платёжный шлюз, интеграция с лабораторией) |
| Data Minimization | Схемы форм, валидация полей, отказ от избыточных полей | Запись, регистрация, лаборатория |
| Data Lineage | DataHub / Apache Atlas, `lineage:`-теги, ETL-логирование | Озеро данных, ETL, БД |
| Классификация и тегирование | DataHub + DLP + OpenAPI `x-data-classification` + CI-linter | Все процессы |
| RBAC | Роли: doctor, admin, cashier, accountant, warehouse, patient | Все процессы |
| ABAC | Атрибуты: branch, shift, own_patient, consent | Запись, медкарта, анализы |
| Шифрование at-rest | TDE (PostgreSQL/1С), KMS (Vault/AWS KMS), AES-256 для файлов | БД, 1С, сканы, озеро |
| Шифрование in-transit | TLS 1.2+, mTLS для сервис-сервис, замена OLE на TLS-API | ККМ↔1С, 1С↔1С, лаборатория, портал |
| DLP | Microsoft Purview / SearchInform | Файлы, почта, сканы, выгрузки |
| Аудит доступа | Аудит-лог C/R/U/D, WORM-хранилище, SIEM | Все процессы |
| MFA / PAM | Duo / Microsoft Entra, Teleport / HashiCorp Vault | AD/LDAP, админ-доступ |
| SIEM / UEBA | Elastic Security / Wazuh + UEBA | Все процессы, особенно `sensitivity:high` |
| Retention и удаление | Политики retention, автоудаление, DSR-процесс | Все процессы |
| Согласие субъекта | Сервис согласий, аудит согласий | Запись, медкарта, анализы |
| API-контракты с классификацией | OpenAPI + `x-data-classification`, API Gateway | Лаборатория, портал, платёжный шлюз |
| Изоляция пациентов | Tenant isolation по `patient_id`, row-level security | Портал, мобильное приложение, анализы |
| Обезличивание для аналитики | ETL-обезличивание, псевдонимизация, агрегация | Озеро данных, BI/ML/AI |

**Вывод:** целевая архитектура закрывает все ПЗ через конкретные инструменты и механизмы. Внедрение поэтапное: сначала классификация/теги и RBAC/ABAC (фундамент), затем шифрование и DLP, затем SIEM/UEBA и Data Lineage, затем озеро данных с обезличиванием.
